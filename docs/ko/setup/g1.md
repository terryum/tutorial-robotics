# Unitree G1 — Setup 검토

**검증 상태: 모든 실물 단계는 `reader_test_required`.** 이 안내는 모델별 설치 검토를 준비하기 위한 문서입니다. 시뮬레이션 모델로 보유 장비를 식별하지 마세요. 실물 모델·좌우·리비전·펌웨어·컨트롤러·SDK는 로컬에 기록하고 일련번호·주소·보정값은 Git에서 제외합니다.

실물 작업 전 [하드웨어 안전](../../07_SAFETY.md)을 읽으세요. 해당 매뉴얼, 제조사 지정 고정구와 전원, 보호 접지, 정지 장치, 격리 네트워크, 작업자를 준비합니다. 설치·보정·제어 활성화·동작은 장비별 절차와 해당 실행 승인이 필요합니다. 아래 명령은 합성 데이터만 검사합니다.

## 구성 식별과 지지 준비

23 DoF, 29 DoF, 허리 고정 여부, 실제 EDU 옵션을 구분합니다. 과정의 Menagerie 모델은 액추에이터 29개와 부유 베이스를 갖지만 실물 구성이나 EDU 권한을 증명하지 않습니다.

지정된 지지·인양 장치, 리모컨, 맞는 배터리·충전기와 EDU 허리 고정 가이드를 준비합니다. **G1 User Manual**의 기동·종료 순서를 지지된 로봇과 비워진 작업영역 기준으로 검토합니다. 별도 **Remote Control**의 페어링·정지 조작과 **Battery & Charger**의 취급·충전·보관·표시등 절을 읽습니다. 전원이 꺼진 상태에서 배터리 손상과 체결을 확인합니다. 지지 장치 부족, 팩 손상, 불명확한 표시등, 충전기 불일치가 있으면 기동 준비를 중단합니다. 보관본은 페이지 이미지 전체이며 변환 PDF 첫 페이지에는 변환 표시가 추가되므로 인쇄 제목·쪽수를 기준으로 읽습니다.

## 소프트웨어와 SDK 인덱스

SDK2 Python은 지원되는 EDU 구성과 제조사 지정 통신·소프트웨어 조합에 사용합니다. 정확한 릴리스와 인터페이스 선택을 로컬에 기록합니다. G1 low-level 예제는 슬롯 29개를 정의합니다.

| SDK 슬롯 | 의미 | 적용 조건 |
|---|---|---|
| 0–11 | 좌우 다리 | 두 구성 공통 |
| 12 | 허리 yaw | 두 구성 공통 |
| 13–14 | 허리 roll/pitch | 23 DoF 또는 허리 고정 29 DoF에서 무효 |
| 15–19, 22–26 | 어깨·팔꿈치·손목 roll | 두 구성 공통 |
| 20–21, 27–28 | 손목 pitch/yaw | 23 DoF에서 무효 |

유효 관절을 선택해도 SDK 원래 ID를 유지합니다. 압축한 23개 배열의 위치를 SDK ID로 간주하면 안 됩니다. 모델 `qpos`에는 부유 베이스 좌표도 들어갑니다. PR pitch/roll과 AB 병렬 액추에이터 모드는 구분되며 관절 이름만으로 액추에이터 대응을 추정하지 않습니다.

## 오프라인 실행과 복구

아래 예제를 실행합니다. 테스트는 23 DoF와 허리 고정/해제 29 DoF도 검사하며 유효 개수는 각각 23·27·29개입니다. 관절 순서를 바꿔도 값이 유지되고 누락·중복·SDK 슬롯 불일치는 실패해야 합니다.

upstream `g1_low_level_example.py`는 `MotionSwitcherClient.ReleaseMode()`를 호출하고 반복 명령 스레드를 시작하며 motor command mode를 설정하고 `LowCmd`를 발행합니다. 읽기 전용 subscriber가 아닙니다. 이번 예제는 Unitree SDK를 import하거나 명령을 전송하지 않습니다. 실물 식별·지지·펌웨어·정지 상태 근거가 없으면 하드웨어 lesson은 미완료로 유지합니다.
