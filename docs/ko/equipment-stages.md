# 최소 장비부터 시작하는 학습 순서

읽는 순서는 필요한 장비가 점차 늘어나도록 구성합니다. 호환성을 위해 카탈로그 순서는 유지하고, 경로 안내와 이 문서가 교육 순서를 설명합니다. 로봇 팔·손·이동형 로봇을 소유하지 않아도 개념을 배울 수 있습니다. [장비 역량](equipment.md)이 실제 실행을 결정하고, [전체 수업 목표](lessons.md)가 정확한 선행 조건을 설명합니다.

| 단계 | 최소 장비 | 경험과 근거 | 다음 단계 조건 |
|---|---|---|---|
| 1. 공통 기초 | 맥북 또는 Windows/Linux 노트북 | Python·상태·모델·그래프: core-00–core-04 | 단위·좌표계·재현성 설명 |
| 2. 로컬 로봇공학 | 지원되는 Core 환경, 로봇/XR 불필요 | FR3 제어/IK·Enlight 모델·Shadow/Wuji·Stretch·짧은 PPO/BC·오프라인 입력 | 산출물 확인, 실행과 성능 구별 |
| 3. GPU 시뮬레이션 | 검증된 로컬/원격 NVIDIA 워크스테이션 | Isaac Sim 자산·PhysX·카메라·동일 조건 엔진 비교·학습 | 실제 엔진 산출물과 독립 평가 |
| 4. 선택형 사람 데이터 | WS와 선택한 Quest 3·MANUS 장갑·VIVE 트래커 | 읽기 전용 입력 → 정합 → sink → 시뮬레이션 에피소드 | 실제 입력과 합성 재생을 구별하여 검증 |
| 5. 데이터→정책 | 검증 GPU와 기록 데이터, 선택형 UMI 수집기 | 에피소드 분리·BC/VLA·Isaac Lab/Teleop | 보류 데이터와 독립 시뮬레이션 평가 |
| 6. 마지막 실물 로봇 | 검토한 FR3 또는 Flexiv Enlight, 손 경로에만 Wuji | 오프라인 재생 → sink → 읽기 전용 → 섀도 → 토크 비활성 재생 → 새 정확한 동작 승인 | 장비·도구·하중·정지 근거와 실행별 승인 |

## 노트북 입문: Windows가 네이티브 Core 검증을 뜻하지 않습니다

카탈로그의 휴대용 Core 지원은 macOS arm64와 Linux x86_64입니다. Windows 노트북으로 교재를 읽고 지원 원격 호스트에 연결하거나, 별도로 검사한 Linux 환경을 사용할 수 있습니다. [Microsoft WSL](https://learn.microsoft.com/en-us/windows/wsl/install)은 Windows에서 Linux를 제공하지만, 그것만으로 이 교재·그래픽·GPU 환경의 실행을 보증하지 않습니다. 배포판·아키텍처·Python·MuJoCo 렌더링·산출물을 확인해야 로컬 성공을 주장할 수 있습니다. Windows 호스트 이름만으로 Ubuntu/Isaac 검증을 추론하지 않습니다. 대안은 [노트북 원격 설정](setup/remote-development/laptops.md)에 있습니다.

## 초반 로봇 구매가 필요 없는 매니퓰레이터 경로

1. 노트북: 공통 기초 → FR3 구조·PD·중력·자코비안/IK·작업 공간 제어·접촉·궤적. 시뮬레이션 FR3면 충분합니다.
2. 노트북 학습: 도달 환경 → 짧은 PPO → 시연/BC → 독립 평가. Enlight는 자체 모델로 학습하며 FR3 정책을 후보로 재사용하지 않습니다.
3. GPU: 실제 PhysX 제어·학습 → MuJoCo/PhysX 동일 조건 근거 → Isaac 카메라·합성 데이터. [NVIDIA 경험 워크북](nvidia-ecosystem.md)을 사용합니다.
4. 선택형 수집: `core-teleop-01` → `sim-teleop-01` → `sim-teleop-02` → `sim-enlight-06`. 실제 입력이 막혀 있어도 오프라인 정합을 배울 수 있지만, 장비 입력 수업 완료를 대신하지 않습니다.
5. 시뮬레이션 배포 후보와 오프라인 runtime sink 후, 마지막에 실물 읽기 전용 준비를 합니다. 프로브 접촉과 집기·이동·놓기는 별도 도구/제어기가 필요한 마지막 분기입니다.

[매니퓰레이터 정식 경로](paths.md)의 정확한 선행 조건은 유지합니다. 선택형 수집 경로가 일반 제어·학습에 XR 장비를 필수로 만들지는 않습니다.

## 입력 장비를 목적에 맞게 재사용하기

| 장비·선택지 | 교육에서의 역할 | 로컬에서 확인할 항목 |
|---|---|---|
| Meta Quest 3 | 시점·컨트롤러·클러치/데드맨, 선택형 손 입력 | 추적·로컬 수신 시각·해제/재연결·선택 파이프라인/버전 |
| MANUS 햅틱 장갑 | 손가락 자세와 손 리타게팅 | 정확한 모델·펌웨어·SDK/권한·보정·시각 의미 |
| HTC VIVE Ultimate Tracker | 손가락 각도와 독립된 손목/몸체 위치·자세 | 트래커 모델·Hub/SDK 프로토콜·장착/월드 변환·추적 유효성 |
| Wuji Hand 2 Beta 2 | 시뮬레이션 정교 손, 마지막에 실물 읽기 전용 | 관절 이름·한계·촉각 보정·별도 실물 게이트 |
| UMI 계열 수집기 | 평행 2지 과제의 로봇 없는 시연 데이터 | 카메라/자세/폭 동기화·보정·대상 로봇의 실행 가능성 |

여기서 의도한 제품명은 **HTC VIVE Ultimate Tracker**이며 드라이버 선택 전에 실제 라벨을 확인합니다. MANUS Pro Haptic·Metagloves Pro·구형 Haptic의 SDK 식별 정보는 동일하지 않습니다. [MANUS 문서](https://docs.manus-meta.com/latest/Products/Metagloves%20Pro%20Haptic/)는 모델별 확인 출발점입니다. 햅틱 피드백은 출력/구동 경로이므로 손가락 자세 읽기가 햅틱 활성화를 승인하지 않습니다.

Ubuntu에서는 저장소의 [고정된 VR 설정](setup/vr-teleop.md)과 [실제 검증 기록](../verification/vr-teleop-2026-11-13.md)을 따릅니다. Linux Hub 아카이브와 소켓 테스트는 실제 장비 입력 근거가 아닙니다. 별도의 [HTC 제품 페이지](https://www.vive.com/us/accessory/vive-ultimate-tracker/)는 소비자 PC-VR 경로를 설명하며, Windows 요구사항이 Linux beta·Quest 연동 검증을 뜻하지는 않습니다. 기존 VR 환경을 보존합니다. 개인 보유 목록·장비 식별자·비공개 로봇 연동은 공개 교재에 기록하지 않습니다.

## 이후 어떤 구매를 검토할까요?

초반 장에는 로봇·헤드셋·장갑·트래커 추가 구매가 필요하지 않습니다. VLA pick-and-place 종합 실습에는 호환되는 **평행 2지 그리퍼**, 손목/작업 장면 RGB 카메라, 알려진 마운트·도구·하중, 보정한 작업 공간을 계획합니다. Robotiq 2F-85는 저장소의 시뮬레이션 기준이며 구매 확정이나 Enlight 호환 검증이 아닙니다. 개구 폭·힘/속도·질량·장착·전원/통신·정지/상태 API·지연·시뮬레이션 결합을 확인한 뒤 모델을 고릅니다. 팔이 있어도 카메라나 마운트가 부족할 수 있습니다.

UMI 키트는 해당 행동 표현으로 로봇 없는 시연을 수집하려는 경우에 검토합니다. [원본 UMI 프로젝트](https://umi-gripper.github.io/)는 손에 드는 평행 그리퍼와 카메라를 사용하며 장갑의 대체품이나 모든 로봇의 완성 어댑터가 아닙니다. 영상 관측·폭·상대 자세를 정책/로봇 스키마와 먼저 맞춥니다. 작은 수집 검증부터 시작하며 NVIDIA 입문을 위해 새 휴머노이드나 Jetson을 먼저 살 필요는 없습니다. 이 안내는 구매나 설치를 실행하지 않습니다.

## 장비가 늘어도 동작 권한은 늘어나지 않습니다

합성 입력·실제 사람 입력·시뮬레이션 정책 성능·실물 동작은 별도 주장입니다. 각 단계의 근거로 확인합니다. 사용할 수 없는 단계는 차단 상태로 두고 이전 학습을 보존합니다. 마지막 실물 단계는 [안전 규칙](../07_SAFETY.md)을 따르며 앞 단계가 물리 동작을 승인하지 않습니다.
