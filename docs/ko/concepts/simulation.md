# 시뮬레이션: 상태, 시간, 재현 가능한 근거

## 모델과 변하는 상태는 다르다

시뮬레이터는 세계의 모델과 시간을 진행시키는 수치 규칙을 결합한다. 모델에는 관절 구조·기하·질량·관성·한도·적분 설정이 있다. 상태에는 변하는 위치·속도 등이 있다. MuJoCo는 `MjModel`과 `MjData`를 구별한다. 관절 상태 하나를 바꾸는 것은 로봇 기하 정의를 바꾸는 일이 아니다.

설치 중 호스트를 점검한 뒤 [진자 실험](../lessons/core-01.md), [고정 소스](../lessons/core-02.md), [모델 검사](../lessons/core-03.md), [렌더링](../lessons/core-04.md)부터 시작한다. 환경을 별도로 확인할 때는 [호스트 진단](../lessons/core-00.md)을 실행한다. Python만 있다고 모든 런타임이 준비되지는 않는다. 카탈로그는 플랫폼·의존성·구현 상태·검증 상태를 구별한다. 올바른 그림이 올바른 동역학을 보장하지 않는다.

단순 회전계에서 $q$는 rad 단위 위치, $v=\dot q$는 rad/s 단위 각속도다. 개념적인 상태는 $s=[q,v]$이다. 일반 로봇에서 `qpos`는 `nq`, `qvel`은 `nv`개 원소를 가진다. 자유 물체의 쿼터니언은 위치 표현에 4개, 각속도는 3개 원소를 쓰므로 두 수가 다를 수 있다. 구동기 제어 벡터의 길이 `nu`도 별도의 양이다.

## 수치 스텝이 근사하는 것

동역학식의 한 형태는 다음과 같다.

$$
M(q)\dot v+b(q,v)=\tau+J(q)^Tf,\qquad E(t)=K(t)+U(t).
$$

$M$은 일반화 관성, $b$는 편향 힘, $\tau$는 적용 일반화 힘이며 $J^Tf$는 접촉력을 일반화 좌표로 바꾼다. 회전 하나에서는 관성이 kg m², 토크가 N m이다. 회전과 직선이 섞인 시스템은 좌표별 단위를 구별해야 한다. 운동 에너지 $K$, 위치 에너지 $U$, 합 $E$의 단위는 J이다. 시뮬레이터는 유한 스텝으로 연속 변화를 근사하며 모든 궤적을 기호적으로 풀지는 않는다.

[physics.py](https://github.com/terryum/tutorial-robotics/blob/main/src/pai_lab/lessons/physics.py)의 무입력·무마찰 진자는 분포 질량을 가진 캡슐과 RK4를 사용하며 기준 $\Delta t=0.002$ s이다. 점질량 관성 공식으로 바꾸고 동일 동역학을 기대하면 안 된다. 수업은 다음 에너지 드리프트를 측정한다.

$$
d=\max_i|E_i-E_0|.
$$

**측정 출력이 아닌 계산 예제**: 에너지가 [1.000000, 1.000003, 0.999998] J이면 드리프트는 $3\times10^{-6}$ J이다.

```python
import numpy as np
energy_j = np.array([1.000000, 1.000003, 0.999998])
drift_j = np.max(np.abs(energy_j - energy_j[0]))
assert np.isclose(drift_j, 3e-6)
```

## 실험의 시계를 이해한다

진자 수업은 저장 행마다 `mj_step`을 10회 호출하고 `mj_forward`로 파생 상태를 갱신한 다음 샘플을 기록한다. 기준에서 행 간격은 0.02 s이다. 64행이면 시뮬레이션 시간은 1.28 s이다. 컴퓨터에서 실제로 기다린 시간과 시뮬레이션 시간은 다르다. 그래프 행 번호도 샘플 일정이 정해져 있지 않으면 시간이 아니다.

본 실험에서는 적분 간격과 관측 시간 1.28 s를 고정하고 시작 각도를 0.35에서 0.70 rad로 바꾼다. 선택 심화에서는 시드와 표본 수를 유지하고 적분 간격을 0.004 s로 두 배 늘린다. 저장 행 간격은 0.04 s가 되고 전체 시간도 두 배다. 이 비교는 문서의 일정에 따른 드리프트를 조사하며, 같은 경과 시간에서 적분 정확도만 분리하지는 않는다. 같은 시간 구간을 비교하려면 별도 실험으로 설계하고 바뀐 샘플 일정을 명시한다.

## 상태와 출처를 산출물에서 찾는다

`experiment.json` → `payload` → `state`는 `[time_s, q_rad, qvel_rad_s]` 행을 담고, `dt_s`는 적분 스텝이다. `trace.csv`는 시간에 따른 초기 에너지 기준값과 측정 에너지를 담고, `summary.json`은 J 단위 `energy_drift`를 보고한다. 수치 검사는 실제 값으로 재계산해 $10^{-5}$ J보다 작은지 확인한다. 성공 플래그만으로는 부족하다.

`run.json`과 산출물 해시는 실행을 코드·파일에 연결한다. [models.py의 `provenance`](https://github.com/terryum/tutorial-robotics/blob/main/src/pai_lab/lessons/models.py)는 벤더 바이트를 `assets/model-lock.json`과 대조한다. 벤더 캐시는 읽기 전용으로 유지하고 변환 결과는 무시되는 실행 폴더 안에 둔다. 같은 시드라도 모델 바이트·엔진 버전·소스·전처리가 달라지면 재현을 보장하지 못한다.

[공개 검증 보고서](../../verification/reader-experience.md)는 측정 예제와 소스 리비전을 명시한다. 당시 관측을 설명하며 현재 체크아웃의 새 결과는 아니다. 모델이나 엔진이 없으면 `capability-unavailable`로 남겨야 하며 합성 성공을 만들면 안 된다.

## 이해 확인

1. `nq`, `nv`, `nu`가 다른 이유는? 위치·속도 좌표·구동기 입력은 서로 다른 공간이기 때문이다.
2. 작은 에너지 드리프트가 좋은 제어기를 뜻하는가? 무입력 모델의 수치 특성 하나를 검사할 뿐, 제어기는 평가하지 않았다.
3. 재현 비교에서 고정할 것은? 선택 변수 외의 모든 선언 입력과 모델·소스·소프트웨어 식별이다.

다음으로 [기구학](kinematics.md)에서 관절과 도구 위치를, [제어와 접촉](control-contact.md)에서 힘과 운동을 연결한다.

## 장비 확장 순서

[장비 단계](../equipment-stages.md)를 따라 노트북 시뮬레이션, 검증된 GPU 런타임, 선택형 XR·장갑·트래커·UMI 수집, 마지막 실물 로봇 순으로 진행한다. 카탈로그에는 학습 수업 71개와 Core 진단 1개가 있다. 학습 수업은 Core 32개, Sim 27개, Hardware 12개다. 기존 휴대형 범위는 Core 32개와 배포·오프라인 sink이며 선택형 `core-teleop-01`의 가벼운 합성 입력 수업을 더하면 35개다. 이 개수는 Mac 실제 VR 입력 검증을 뜻하지 않는다. 실물 수업 11개와 실제 입력 `sim-teleop-01`은 scaffolded이며, 하드웨어 단계에서 구현된 예외는 오프라인 sink다.
