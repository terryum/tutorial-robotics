# Unitree G1 — Setup review

**Verification: `reader_test_required` for every physical step.** This guide prepares a model-specific installation review. A simulated robot does not identify your equipment. Record model, side, revision, firmware, controller and SDK locally; keep serials, addresses and calibration out of Git.

Before physical work, read [hardware safety](../../07_SAFETY.md). Prepare the matching manuals, manufacturer-specified fixture and power supply, protective-earth provisions, stop device, isolated network and an operator. Installation, calibration, enabling control and motion require the appropriate device procedure and per-run approval. The commands below only inspect synthetic data.

## Identify the configuration and prepare support

Distinguish 23 DoF, 29 DoF, locked-waist configurations and the actual EDU option. The course's Menagerie model has 29 actuators and a floating base; that does not establish your robot's identity or EDU permissions.

Prepare the designated support/lifting arrangement, remote, correct battery and charger, and the matching EDU waist-fastener guide. Review the **G1 User Manual** start-up/shutdown sequence with a supported robot and clear area. Review the separate **Remote Control** pairing/stop controls and **Battery & Charger** handling, charging, storage and indicator sections. Check battery condition and latching with power off. A missing support fixture, damaged pack, unclear indicator or mismatched charger blocks power-on preparation. The archived G1 manuals are complete page-image editions; their conversion adds a banner above the first page, so use the printed headings/page labels.

## Software and SDK index mapping

Use SDK2 Python only with the supported EDU configuration and vendor-specified transport/software. Record the exact release and interface choice locally. Its low-level G1 example defines 29 indexed slots:

| SDK slots | Meaning | Applicability |
|---|---|---|
| 0–11 | Left/right legs | Both configurations |
| 12 | Waist yaw | Both configurations |
| 13–14 | Waist roll/pitch | Invalid on 23 DoF or locked-waist 29 DoF |
| 15–19, 22–26 | Shoulders, elbows, wrist roll | Both configurations |
| 20–21, 27–28 | Wrist pitch/yaw | Invalid on 23 DoF |

Keep full SDK indices while selecting valid joints. A compact 23-value vector must never be indexed as though its offsets were SDK IDs. Model `qpos` also includes floating-base coordinates. PR pitch/roll and AB parallel-actuator modes are distinct; do not infer an actuator mapping from a joint name.

## Offline action and recovery

Run the example below; tests also exercise 23 DoF and locked/unlocked 29 DoF. Expected valid counts are 23, 27 and 29 respectively. Reordered joint entries preserve their values; absent, duplicate or mismatched SDK slots fail.

The upstream `g1_low_level_example.py` invokes `MotionSwitcherClient.ReleaseMode()`, starts a recurrent command thread, sets motor command modes and publishes `LowCmd`. It is not a read-only subscriber. Our example imports no Unitree SDK and sends no command. If identity, support, firmware or stop-state evidence is absent, leave the hardware lesson incomplete.
