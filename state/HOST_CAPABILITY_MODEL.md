# Host Capability Model

| Host label | Execution mode | Typical capability set | Constraint |
|---|---|---|---|
| MacBook | DEVELOPMENT | dev_core, MuJoCo, rendering, small ML, LeRobot small, optional ROS 2 | no native CUDA/Isaac/vendor runtime |
| WS2 | DEVELOPMENT | all MacBook development capabilities plus Ubuntu Jazzy, CUDA, mjlab, Isaac, GPU VLA | no real command while development jobs run |
| WS2 | ROBOT_RUNTIME | vendor runtime, isolated NIC, selected hardware | development batch stopped |
| WS1_WINDOWS | DEVELOPMENT | Windows input/device tools; user reports OS installed | pairing, calibration and streaming require local verification |
| WS1_UBUNTU | DEVELOPMENT | core-dev, MuJoCo, native Jazzy, rendering | offline checkout; no hardware authority |
| WS1 | ROBOT_RUNTIME | stable vendor runtime, teleop, recorder, safety, inference | avoid experimental retraining/upgrades |

Actual truth is `.local/HOST_CAPABILITIES.md`, generated by `$bootstrap-host`. Host names are recommendations, not authorization.

WS1 and WS2 are dual-boot hosts. Native Ubuntu and WSL2 are distinct environments; one physical PC cannot run its two native OS installations concurrently. Re-audit before each runtime mode change.
