# Tutorial Robotics common learner workflow

For lesson execution, read curriculum/catalog.json, this workflow, the selected bilingual lesson, and local state in that order. For generic repository installation/start prompts, first use the preparation route below. The catalog order and pal are authoritative for both Codex and Claude Code.

## Prompt-first installation and start invitation

Treat `https://github.com/terryum/tutorial-robotics 이 레포를 받아서 설치해주고 튜토리얼을 시작해줘` and an equivalent generic “clone this repository, install it and start the tutorials” request as **prepare, verify, then invite**. The request authorizes the ordinary minimal Core setup after showing its plan. It does not authorize opening or running the first lesson before an actual start reply. A request that explicitly names running T00/core-00 is different: after readiness, proceed with that authorized one-lesson workflow without this extra invitation. Quoting either prompt while editing documentation does not execute it.

1. **Locate or clone safely.** Identify the user's requested workspace and actual working directory. If a suitable `tutorial-robotics` clone already exists, inspect its repository identity and `git status --short`; preserve its branch, unrelated changes and ignored `.local/` learner history. Do not reset, overwrite, silently switch branches or create a second learner history. Do not fetch/pull an existing clone unless the user explicitly requests an update and the working tree can be handled safely. If no appropriate clone exists, clone the public repository into a new non-conflicting directory. A missing Git/network permission is a real blocker; report it instead of claiming a checkout exists.
2. **Read this checkout, not remembered context.** Read `README.ko.md` for Korean or default `README.md` for English, then `AGENTS.md`, `CLAUDE.md` when present, `curriculum/catalog.json`, this workflow and `bootstrap.sh`. Read the checkout-local `bootstrap-host` and `tutorial-robotics` skill files for the current agent. A clone created from a parent working directory may not expose its new local skills automatically: read them by explicit checkout path and run tools with that checkout as working directory. Do not rewrite global agent configuration or assume a role/skill has become discoverable. Preserve any existing custom hooks while following this checkout's credential-guard instructions.
3. **Plan and apply only the requested setup.** Run `sh bootstrap.sh --plan` in the checkout before Python/pal exists. Show the detected native OS/architecture, disk, missing tools, purpose, environment location and commands. The script supports Darwin/arm64 and Linux/x86_64; Windows requires an actually supported Linux/WSL or remote environment, not an invented native pass. On an existing checkout with `.venv`, first perform the current verification/platform checks and all declared Core imports plus plotting/image imports in step 4. If they already pass, reuse that working environment and skip `--apply`; do not resync/reinstall it on every pasted onboarding prompt (`uv sync --no-dev` can remove development extras). If the requested Core environment is missing or fails those checks, apply only the displayed minimal necessary Core setup/repair with `sh bootstrap.sh --apply`, without another ordinary plan-approval question. Keep unsupported platforms or unapproved external requirements blocked rather than treating a repair as successful. A readiness-only audit stops at read-only checks and never applies installation. Respect actual tool approval, network, system-package and EULA requirements; do not bypass them or auto-install GPU/ROS/Isaac, firmware or large models.
4. **Verify real readiness in the selected environment.** Use this checkout's explicit executables, so a shell activation from a previous tool call is unnecessary:

   ```bash
   .venv/bin/pal host detect --json
   .venv/bin/pal setup verify --profile core --json
   MPLBACKEND=Agg .venv/bin/python -c 'import sys, numpy, mujoco, gymnasium, scipy, matplotlib; from matplotlib import pyplot; from PIL import Image; assert sys.version_info[:2] == (3, 12); print("Core imports verified")'
   ```

   Inspect both exit status and JSON. `setup verify` returns `profile`, `ready`, `missing_capabilities`, `capability_status` and `host`; require `profile=core`, `ready=true`, an empty missing list and `state=available` for python-3.12, numpy and mujoco. `host` exposes native `system`, `machine`, `platform_id`, `capabilities` and evidence. Confirm a supported native platform as well; Core profile readiness alone checks dependencies. The Core profile checks only python-3.12/numpy/mujoco; it does not validate all declared Core dependencies or plotting. The separate real import check must succeed for NumPy, MuJoCo, gymnasium, SciPy, Matplotlib and Pillow (`PIL.Image`), without creating a plot or running a lesson. Use this same complete import/platform/JSON gate before deciding an existing environment can skip apply and again after any necessary repair. Module discovery alone is not successful import. A stale receipt, executable name or script's final “Ready” line alone is insufficient. If setup, dependency import, platform or required first-lesson capability is unavailable/unverified, explain the exact blocker and do not send a readiness invitation.
5. **Preserve learning state while preparing.** Inspect existing `.local/progress.json`, `.local/session.json`, `.local/browser.json`, helper registration `.local/personal-progress.json` and, when present, `.local/personal-progress-cache.json` without modifying them. Registration is active only when `enabled` is true, `registered_root` resolves to this checkout and `helper` is a valid argument list, subject to the existing developer-state override rules. An enabled registration with missing, malformed, unverified or stale cache means **unknown history**, not a new learner. The helper response schema uses `schema_version=1` and a `lessons` list; failed exchange can expose `sync.status=pending`. There is no universal cache freshness timestamp/TTL in this adapter: do not invent one or treat a missing/pending/stale cache, or its fallback empty `lessons`, as proof of empty history. A local lack of progress/session does not override unresolved registered history. Preserve the registration; do not disable it to select lesson zero. Preparation does not run `pal course init`, `pal lesson run/review/finish`, comparisons or a viewer. Defer course/lesson CLI calls until the start reply: the course/lesson CLI can exchange registered personal history, and `course resume` updates session state. Do not infer a fresh learner from an absent current-chat transcript or an unactivated shell. The bootstrap may install environment files and create `.local/bootstrap-verification.json`; it does not authorize learner-state initialization. Its printed `course init`/`course next` suggestions are instructions for the later learning stage, not actions to follow now.
6. **Invite and stop before the lesson.** Only when first-lesson/Core readiness is verified and history is actually known to be new (no local session/completion and no unresolved enabled helper history), finish preparation with exactly:

   **첫번째 튜토리얼을 띄울 준비가 되었습니다. 시작하시겠습니까?**

   English equivalent: **The first tutorial is ready to open. Would you like to start?**

   Wait for an actual affirmative reply, for example `네, 첫번째 튜토리얼을 시작해줘.` or `Yes, start the first tutorial.` No elapsed time, preselected option or previous install-and-start phrase counts as that reply. Do not open/navigate the first lesson tab, initialize progress, execute or complete a lesson while waiting. If saved progress/session exists, acknowledge its current lesson/phase and invite continuation instead of claiming lesson zero is new: `저장된 학습 상태를 확인했습니다. 이어서 진행하시겠습니까?` / `I found your saved tutorial progress. Would you like to continue?` State any known next-lesson capability blocker rather than promising that an unverified GPU/device lesson is ready. Never erase saved progress to make the fresh-learner invitation fit. If enabled helper history is unknown, do not claim lesson zero or saved completion: state that Core preparation passed but registered history is not yet resolved, then use the distinct invitation **Core 환경 준비를 마쳤지만 등록된 학습 이력은 아직 확인되지 않았습니다. 이력을 확인하고 이어서 진행하시겠습니까?** / **The Core environment is prepared, but registered learning history is not yet verified. Would you like to check it and continue?** Wait for the actual reply without exchanging history or opening a lesson.
7. **After the actual reply, enter learning once.** Re-read local state and current readiness because they may have changed while waiting. If a helper registration is enabled, first resolve its history through the normal registered CLI/helper flow authorized by this start reply, for example `.venv/bin/pal course list --json`, without initializing or choosing a lesson. Preserve its output and diagnostic status: the CLI may exit zero even when helper exchange reports synchronization pending/unavailable. Inspect actual exchange success/pending and the returned/cache history, then reread resulting progress/session and select the saved phase or eligible next lesson. Do not use course-next selection itself as the first unknown-history resolution step. Do not initialize Core or choose core-00 before resolving that registered history. If synchronization remains pending/unverified, keep history unknown and explain the blocker; do not interpret the adapter's empty fallback as a new learner. Only after history is resolved as genuinely new, initialize Core selection if needed, preserving existing records, then select core-00. For an existing learner, use the saved session and `pal course resume`/`pal course next --json` as appropriate; preserve named-path selection and pending feedback rather than restarting T00. Check the selected lesson's full prerequisites, assets, platform, implementation and capabilities before executing it. Follow the companion-tab language rules below, open the selected GitHub lesson, then guide exactly one eligible lesson. An explicit request to restart T00 uses a fresh run directory and preserves earlier completion evidence. Real hardware always retains its separate fresh per-run gates.

### A fresh conversation is a fresh audit, not a fresh learner

After a cleared/new conversation, locate the actual checkout again and reread the same entry files and on-disk session/progress/browser state. Verify the environment from its explicit executable paths. Do not assume the previous cwd, activation, selected lesson, finished setup or browser handle survived. A cached bootstrap receipt is evidence to inspect, not a replacement for current checks. An enabled helper whose cache is missing/unverified/stale remains unknown history after a chat reset; the distinct history-check invitation and post-reply resolution order still apply. An existing tutorial tab's observed language takes priority when learning resumes; if unavailable, preserve the last saved observed language, then use conversation language only for a genuinely fresh selection. A context reset never grants setup, reset, update, lesson or physical-action authority beyond the user's current request.

## Companion GitHub lesson tab

Once lesson execution is authorized, open the selected lesson's rendered GitHub Markdown page before that lesson's setup or explanation. The prompt-first preparation stage above stops at its invitation before opening/navigating a lesson; this narrow exception does not delay an explicitly requested T00 run, next lesson or rerun. First-time learners start with `core-00`; next and rerun requests use the lesson selected by the workflow below. Initialize the lesson language from the Codex/Claude Code conversation (`ko` for Korean, `en` for English), not the browser's UI language. `https://github.com/terryum/tutorial-robotics/blob/main/docs/ko/lessons/core-00.md` is the first Korean lesson. Replace the canonical lesson ID and language for subsequent lessons; do not use a legacy alias such as T00 in the filename.

Every bilingual curriculum page has a top-right `한국어 | ENGLISH` switch linking to the same page in the other language. Before navigating an existing tutorial tab, read its current URL: `/docs/ko/` or `/docs/en/` is the reader's latest language choice and takes precedence over the original conversation language and saved state. Keep that language for next lessons, reruns, lesson links and teaching explanations until the reader switches again or explicitly requests another language in chat. An ordinary Korean/English message is not itself a request to reset the selected language. Do not navigate first and erase a manual language switch. Record the observed language in ignored `.local/browser.json`; if the tab is unavailable, use the last observed language, then the conversation language for a fresh session. A switch made just before a tab was closed cannot be detected without observing that URL. Native Next lesson links are relative and stay in the selected language.

Use the environment's supported browser tools and instructions. Reuse the tutorial tab from this session, or an existing tab showing this repository's lesson; create one new tab only when there is no suitable tutorial tab. Navigate that same tab when the lesson changes. Never repurpose an unrelated tab or close the reader's other tabs. Keep the tab handle in the browser session; if continuity across sessions is needed, store only its browser/tab ID, lesson, language and URL in ignored `.local/browser.json`, and validate it against live tabs before reuse. A stale or closed tab is not a reason to overwrite another tab.

Confirm the page loaded with the correct lesson heading, then include its clickable GitHub link in the opening explanation. Direct the reader to the relevant Expected, Observe or How it works section as the explanation proceeds. Keep the chat/terminal and GitHub theory page available together; a simulation/replay viewer is a separate window when the lesson calls for it. Opening a documentation page does not run a simulation or authorize hardware.

If browser control is unavailable, say so, provide the exact lesson link and supported connection/manual-opening instructions, and continue independent setup or execution. Do not claim the tab opened or was reused without verification. `pal` remains usable in headless terminals and automated checks; browser navigation belongs to guided agent orchestration. Local unpublished edits may differ from GitHub: disclose that difference rather than publishing automatically.

On macOS, when browser connector tools are absent and Chrome is the requested browser, run `python scripts/open_lesson.py core-00 --language ko` (replace canonical ID and initial conversation language). The wrapper invokes `open-lesson-chrome.applescript`, prefers the recorded tutorial tab, observes its language before navigation, checks the resulting URL/title, and saves the tab/language receipt. Its JSON result reports the selected language; use it for the lesson explanation. Use `--force-language` only when the reader explicitly requests a language change in chat. Follow the environment's GUI/automation permission requirements. This opens documentation only and does not establish an extension connection.

## Lesson execution

1. Before Python or pal is available, run `sh bootstrap.sh --plan`. Show OS, architecture, free disk, missing tools, installation purpose, location and commands. For a readiness-only request do not apply or write state.
2. On an authorized setup request, apply only the smallest shown Core plan with `sh bootstrap.sh --apply`. The generic install-and-start route then verifies readiness and waits at its start invitation; do not continue these learning steps until the actual reply. Reuse the local environment and lockfile. Never automatically install system packages, drivers, CUDA, ROS distributions, Isaac Sim, firmware or large models.
3. Use the selected checkout environment (`.venv/bin/pal`, or `pal` after activation) for `host detect --json` and `setup verify --profile core --json`. Inspect current status/evidence and the complete NumPy/MuJoCo/gymnasium/SciPy/Matplotlib/Pillow import and native-platform gate in the preparation section, without plotting; the Core profile alone checks only three dependencies. These checks are read-only. `pal course init` preserves completed records but writes selection state, so run it only in the authorized learning stage when initialization is needed.
4. Read `.local/session.json`, `.local/progress.json` and `pal feedback list --json` to resume. Use `pal course list --json` for completed and pending lessons, `pal course status --json` for remaining/review-needed lessons, and `pal course next --json` for selection. For 진도 확인 / progress, use `pal course summary --json`. Resume from local state by default. With an explicitly registered personal helper, list/status/next consult the same learner's shared history and summary includes the last shared lesson/phase and unresolved-feedback flag. Resume shared context without inventing local run paths. A fresh unregistered clone starts with no completed lessons. `PAL_LOCAL_DIR` can select an independent ignored development session; never mix its results into learner progress.
5. For “다음 단계 실행해줘” / “next”, select exactly one eligible lesson with `pal course next --json`. For “다시 실행해줘” / “rerun”, use the current session lesson and a fresh run directory, preserving earlier evidence. Open or navigate the companion GitHub lesson tab before explaining or executing that lesson.
6. Read the lesson goals and preflight. Check platform, imported dependencies, pinned model identity/hashes, prerequisites and implementation status. Missing capability means capability-unavailable, never success. A publication badge is independent of local evidence.
7. Run the baseline. `pal lesson run` records execution, not completion. Inspect the actual JSON/CSV/NPZ values and plots/renderings, then run `pal lesson check ID --run-dir PATH --json`.
8. Explain the measured values, axes, units, data flow and equation to a reader with basic Python. Execute the documented one-variable comparison; explain invariance honestly when applicable.
9. Immediately persist every “[개선점] …” using `pal feedback add 'original text' --lesson ID --json`. Preserve original text, lesson, receipt time, urgency and status. Feedback after completion but before another lesson starts belongs to the previous session lesson.
10. For “[개선점] 지금 바로 고쳐줘”, store it with `--urgent`, safely interrupt the current software experiment, preserve its interrupted run, fix and reverify, then resume the same lesson in a fresh run. Never interrupt or command physical hardware through an improvised path.
11. After execution/explanation, collect all pending feedback automatically. Batch compatible fixes. Rerun affected experiments for behavior changes; verify bilingual meaning, instructions and links for document changes. Resolve each item with `pal feedback resolve ID --evidence 'specific change and verification'`. Do not hide unresolved issues as completion.
12. Record the concrete explanation and comparison using `pal lesson review ID --run-dir BASELINE --comparison-run-dir COMPARISON --notes 'observations and interpretation'`. Then use `pal lesson finish ID --run-dir BASELINE --json`. Finish rechecks readiness, artifacts, code identity, review and unresolved feedback.
13. Stop after this one learner lesson. A broader explicit development/batch request may run more lessons in an isolated development state.
14. Physical lessons remain scaffolded / reader_test_required until device evidence exists. Read docs/07_SAFETY.md. Follow offline replay → sink → read-only → shadow → torque-disabled replay → fresh run card → one explicitly approved action. Each real command requires new per-run approval.
15. Learner state, runs, checkpoints, raw data and device details stay under ignored .local/. state/PUBLISHING.md holds shared publication evidence only. By default, do not automatically commit learner progress or push. Exception: an explicitly registered personal helper automatically queues and synchronizes minimal completion/session metadata in its dedicated private branch. It never synchronizes raw evidence, feedback text, browser tabs, device state or approvals. Development overrides disable this integration. Development commits follow the user's explicit development scope.

## Named robot paths and interruption

For “매니퓰레이터 튜토리얼 실행해줘” / “Run the manipulator tutorial”, inspect current progress and select `pal course init --path manipulator --json` if needed. This preserves completion history. Hand and mobile requests select `dexterous-hand` and `mobile-manipulator`. Read `curriculum/paths.json` and the matching `docs/{language}/paths.md`. With a selected path, `pal course next` stops at the first unmet required lesson and reports host/capability requirements. Required Isaac lessons cannot be skipped to call a path complete. Legacy course selection without a path retains its stage/robot/elective behavior.

Before continuing a saved lesson, inspect `pal course resume --json`. Pause with `pal course pause --json`; this preserves the teaching phase, explanation, baseline/comparison paths and parameters. `pal lesson run ID --resume-from PATH --json` inspects a saved run/session and reports the next action; it does not execute. Resume explanation/comparison from complete evidence. Restart short simulations in fresh directories. For long learning, use `pal train run --resume-from CHECKPOINT_DIRECTORY` with identical code/model/data/environment/configuration and a new output directory. SIGINT/SIGTERM stop at update boundaries; directory resume chooses the last intact checkpoint after forced termination. Use `pal train export/import` for hashed training-only transfers; keep device settings, credentials and approvals local. Never automatically resume hardware motion.

Enlight must be trained and independently evaluated on its own model. FR3 weights and joint arrays are not Enlight candidates. A short optimizer run is not a performance pass. Probe force control and gripper pick/transfer/place require separate tool/payload/frame reviews, validated controllers and fresh per-run approvals. Keep missing or unverified tools and description-v4 versus RDK-2.1/v3E.1 compatibility blocked. Hardware lesson execution remains scaffolded until real evidence exists.
