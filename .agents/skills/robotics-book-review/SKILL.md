# robotics-book-review

Read the assigned packet and `agent/book-contract.md`; use [review checklist](references/checklist.md). Inspect source/tests and public evidence directly, rather than accepting the author's conclusion. Report file/section, observed mismatch, impact and concrete correction. Classify blocking issues separately from optional improvements.

For each lesson answer: why learn this; inputs/observations; where symbols appear in code/results; prediction when one variable changes; established scope and next step. This is agent reader-perspective review, never a human learning experiment. Compare Korean/English goals, preconditions, numbers, limitations and links. Check catalog → setup, implementation → math, artifact → interpretation, concept → lesson, language → language and README → final page.

Use read-only product access. Return review through native message; main records read-only review evidence. QA may write only its assigned check outputs/caches. After corrections re-read changed artifacts, at most two iterations. Reject fabricated measurements, unsupported comparisons, or hardware readiness claims. Final approval requires actual integrated document checks, not merely draft existence. Record passed/failed/not_run and unresolved required issues explicitly.
