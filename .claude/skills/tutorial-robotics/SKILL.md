# Tutorial Robotics common learner workflow

Read curriculum/catalog.json, this workflow, the selected bilingual lesson, and local state in that order. The catalog order and pal are authoritative for both Codex and Claude Code.

## Companion GitHub lesson tab

At the start of guided learning, open the selected lesson's rendered GitHub Markdown page before setup or explanation. First-time learners start with `core-00`; next and rerun requests use the lesson selected by the workflow below. Initialize the lesson language from the Codex/Claude Code conversation (`ko` for Korean, `en` for English), not the browser's UI language. `https://github.com/terryum/tutorial-robotics/blob/main/docs/ko/lessons/core-00.md` is the first Korean lesson. Replace the canonical lesson ID and language for subsequent lessons; do not use a legacy alias such as T00 in the filename.

Every bilingual curriculum page has a top-right `한국어 | ENGLISH` switch linking to the same page in the other language. Before navigating an existing tutorial tab, read its current URL: `/docs/ko/` or `/docs/en/` is the reader's latest language choice and takes precedence over the original conversation language and saved state. Keep that language for next lessons, reruns, lesson links and teaching explanations until the reader switches again or explicitly requests another language in chat. An ordinary Korean/English message is not itself a request to reset the selected language. Do not navigate first and erase a manual language switch. Record the observed language in ignored `.local/browser.json`; if the tab is unavailable, use the last observed language, then the conversation language for a fresh session. A switch made just before a tab was closed cannot be detected without observing that URL. Native Next lesson links are relative and stay in the selected language.

Use the environment's supported browser tools and instructions. Reuse the tutorial tab from this session, or an existing tab showing this repository's lesson; create one new tab only when there is no suitable tutorial tab. Navigate that same tab when the lesson changes. Never repurpose an unrelated tab or close the reader's other tabs. Keep the tab handle in the browser session; if continuity across sessions is needed, store only its browser/tab ID, lesson, language and URL in ignored `.local/browser.json`, and validate it against live tabs before reuse. A stale or closed tab is not a reason to overwrite another tab.

Confirm the page loaded with the correct lesson heading, then include its clickable GitHub link in the opening explanation. Direct the reader to the relevant Expected, Observe or How it works section as the explanation proceeds. Keep the chat/terminal and GitHub theory page available together; a simulation/replay viewer is a separate window when the lesson calls for it. Opening a documentation page does not run a simulation or authorize hardware.

If browser control is unavailable, say so, provide the exact lesson link and supported connection/manual-opening instructions, and continue independent setup or execution. Do not claim the tab opened or was reused without verification. `pal` remains usable in headless terminals and automated checks; browser navigation belongs to guided agent orchestration. Local unpublished edits may differ from GitHub: disclose that difference rather than publishing automatically.

On macOS, when browser connector tools are absent and Chrome is the requested browser, run `python scripts/open_lesson.py core-00 --language ko` (replace canonical ID and initial conversation language). The wrapper invokes `open-lesson-chrome.applescript`, prefers the recorded tutorial tab, observes its language before navigation, checks the resulting URL/title, and saves the tab/language receipt. Its JSON result reports the selected language; use it for the lesson explanation. Use `--force-language` only when the reader explicitly requests a language change in chat. Follow the environment's GUI/automation permission requirements. This opens documentation only and does not establish an extension connection.

## Lesson execution

1. Before Python or pal is available, run `sh bootstrap.sh --plan`. Show OS, architecture, free disk, missing tools, installation purpose, location and commands. For a readiness-only request do not apply or write state.
2. On an authorized setup request, apply only the smallest shown Core plan with `sh bootstrap.sh --apply`. Reuse the local environment and lockfile. Never automatically install system packages, drivers, CUDA, ROS distributions, Isaac Sim, firmware or large models.
3. After activation, use `pal host detect --json` and `pal setup verify --profile core --json`. These checks are read-only. `pal course init` preserves completed records.
4. Read `.local/session.json`, `.local/progress.json` and `pal feedback list --json` to resume. Use `pal course list --json` for completed and pending lessons, `pal course status --json` for remaining/review-needed lessons, and `pal course next --json` for selection. Resume from this checkout's local state; do not use another learner's or host's shared report as personal progress. A fresh clone starts with no completed lessons. `PAL_LOCAL_DIR` can select an independent ignored development session; never mix its results into learner progress.
5. For “다음 단계 실행해줘” / “next”, select exactly one eligible lesson with `pal course next --json`. For “다시 실행해줘” / “rerun”, use the current session lesson and a fresh run directory, preserving earlier evidence. Open or navigate the companion GitHub lesson tab before explaining or executing that lesson.
6. Read the lesson goals and preflight. Check platform, imported dependencies, pinned model identity/hashes, prerequisites and implementation status. Missing capability means capability-unavailable, never success. A publication badge is independent of local evidence.
7. Run the baseline. `pal lesson run` records execution, not completion. Inspect the actual JSON/CSV/NPZ values and plots/renderings, then run `pal lesson check ID --run-dir PATH --json`.
8. Explain the measured values, axes, units, data flow and equation to a reader with basic Python. Execute the documented one-variable comparison; explain invariance honestly when applicable.
9. Immediately persist every “[개선점] …” using `pal feedback add 'original text' --lesson ID --json`. Preserve original text, lesson, receipt time, urgency and status. Feedback after completion but before another lesson starts belongs to the previous session lesson.
10. For “[개선점] 지금 바로 고쳐줘”, store it with `--urgent`, safely interrupt the current software experiment, preserve its interrupted run, fix and reverify, then resume the same lesson in a fresh run. Never interrupt or command physical hardware through an improvised path.
11. After execution/explanation, collect all pending feedback automatically. Batch compatible fixes. Rerun affected experiments for behavior changes; verify bilingual meaning, instructions and links for document changes. Resolve each item with `pal feedback resolve ID --evidence 'specific change and verification'`. Do not hide unresolved issues as completion.
12. Record the concrete explanation and comparison using `pal lesson review ID --run-dir BASELINE --comparison-run-dir COMPARISON --notes 'observations and interpretation'`. Then use `pal lesson finish ID --run-dir BASELINE --json`. Finish rechecks readiness, artifacts, code identity, review and unresolved feedback.
13. Stop after this one learner lesson. A broader explicit development/batch request may run more lessons in an isolated development state.
14. Physical lessons remain scaffolded / reader_test_required until device evidence exists. Read docs/07_SAFETY.md. Follow offline replay → sink → read-only → shadow → torque-disabled replay → fresh run card → one explicitly approved action. Each real command requires new per-run approval.
15. Learner state, runs, checkpoints, raw data and device details stay under ignored .local/. state/PUBLISHING.md holds shared publication evidence only. Do not automatically commit learner progress or push. Development commits follow the user's explicit development scope.
