# XR과 로봇 하드웨어 실습

가상 입력과 명령 차단에서 출발한 뒤 시뮬레이터에서 시연을 수집합니다. 실제 로봇을 배우는 단계에서는 Enlight 또는 FR3를 선택하여 제조사 절차와 읽기 전용 확인부터 준비합니다.

## Quest 3 스타일 팔·손 스켈레톤 재생

**합성 입력 재생 · Mac에서 명령 차단 검증**

**예측.** 손목이 계속 움직이는 프레임을 주더라도 추적이 끊기거나, 프레임이 오래됐거나, 클러치를 놓으면 가상의 명령이 얼마가 되어야 할까요? 새 프레임을 받은 뒤 스위치만 다시 눌렀을 때도 답을 예상해 보세요.

```sh
python examples/robotics_ko/xr.py --output-dir outputs/robotics-ko/xr
```

`xr.py`는 양팔의 어깨·팔꿈치·손목 위치(m), 손목의 단위 쿼터니언 `(x,y,z,w)`, 이름이 붙은 다섯 손가락 굽힘각(rad)을 20 ms 간격으로 구성합니다. `frames[].raw.arm_skeletons`에서 팔의 세 점과 각 손가락의 마디 위치를 읽을 수 있습니다. 변환된 손목 위치의 x 성분에서 기준 프레임의 x 성분을 빼서 `requested_delta_m`을 계산합니다. `CommandSink.accept()` 또는 `poll()`이 허용한 경우만 그 벡터를 `command_delta_m`에 기록합니다. 두 스위치를 놓은 뒤 로컬에서 재무장하고 다시 누르는 과정을 거쳐 새 움직임을 허용합니다. 이 코드는 출력 벡터를 파일에 저장합니다.

`xr.json`의 각 `cases`를 보면 이동 중 명령 벡터의 크기는 8 mm, 고장 또는 해제 시 0 mm, 스위치만 다시 눌렀을 때 0 mm였습니다. 재무장 후 새 프레임을 눌러 받았을 때 48 mm를 기록했습니다. 오래된 프레임을 수신하는 경우와 새 프레임 없이 기다리는 경우 모두 100 ms에서 차단됐습니다. `xr.png`에 같은 네 단계의 명령 크기가 표시됩니다.

**한 변수.** 다른 입력은 고정하고 마지막 입력의 나이만 99 ms와 100 ms로 비교한다고 생각해 보세요. 코드의 `now_ns − receive_time_ns >= STALE_AFTER_NS`에서 어느 시점에 멈추는지 답하세요. 지연 계산에는 수신기의 단조 시계를 사용합니다. 서로 다른 장치의 원시 시각은 로그에 보관합니다. [Meta Unity Movement의 모션 추적 예제](https://github.com/oculus-samples/Unity-Movement)

## MANUS 손가락과 VIVE 손목 합성

**합성 입력 재생 · 소스 선택**　**기존 기록 · Ubuntu 합성 시연 수집**　**현장 확인 대기 · 장치 입력**

Quest 입력만 사용하는 모드에서는 양손의 손목과 손가락 입력이 Quest에서 들어옵니다. 통합 모드에서는 VIVE Ultimate Tracker에서 손목 위치와 자세를 받고, MANUS 장갑에서 손가락 관측을 받습니다. 스위치 상태는 Quest 쪽에서 유지합니다. `InputMux.combine()`은 좌우 구분, 이름, 수신 시각과 추적 여부를 확인합니다. 장치 좌표에서 추적기 자세를 받은 뒤, `T_world,wrist = T_world,device T_device,tracker T_tracker,wrist` 순서로 월드 기준 손목 자세를 얻습니다. 마지막 항에는 추적기와 손목 사이 장착 변환이 들어갑니다.

**예측하고 확인하기.** 팔을 고정하고 손가락만 굽히면 손목과 손가락 중 어느 값이 바뀔까요? `xr.json`의 `integrated_sources`를 먼저 확인합니다. 왼손과 오른손 모두 `wrist = vive`, `fingers = manus`가 나옵니다. 실제 장치 실습을 준비할 경우 손목을 고정한 자세의 변환 잔차, 좌우 매핑과 타임스탬프를 읽고 기록합니다. 어느 쪽 입력이라도 신선도나 추적 상태가 맞지 않으면 입력을 계속 전달할 수 없습니다. [MANUS SDK 스켈레톤 스트림](https://docs.manus-meta.com/latest/Plugins/SDK/C%2B%2B/SDK%20Client/) · [VIVE Ultimate Tracker](https://www.vive.com/us/accessory/vive-ultimate-tracker/)

실습 `sim-teleop-02`는 좌표 정합과 명령 차단을, `sim-enlight-06`은 Enlight 팔의 시뮬레이션 수집을 다룹니다. 기록에는 원래 입력, 적용한 관절 목표, 로봇 관절 상태, 카메라 이미지와 수신 시각이 함께 들어갑니다. 학습·검증·테스트 세 묶음은 개별 프레임 대신 전체 에피소드 단위로 나눕니다. 입력을 한 번만 기록한 뒤 인접 프레임을 무작위로 반씩 나눴을 때 평가가 좋게 나오는 이유를 생각해 보세요. [Ubuntu 합성 시연 수집 기록](https://github.com/terryum/tutorial-robotics/blob/main/docs/verification/vr-teleop-2026-11-13.md)

## Enlight 또는 FR3 · 연결 전 확인

**현장 확인 대기 · 로봇과 작업 공간**　**기존 기록 · 오프라인 런타임**

| 준비 단계 | Enlight | FR3 |
|---|---|---|
| 모델과 근거 | Enlight 모델·설치 도구·페이로드·관절 이름·영점을 확인합니다. 부품별 좌표와 제한을 모델과 대조합니다. | FR3 모델·장착 도구·페이로드·관절 이름·영점을 확인합니다. ROS 또는 SDK의 상태 단위와 순서를 대조합니다. |
| 작업 공간과 비상정지 | 작업 영역, 사람의 위치, 고정 상태, 격리 네트워크와 작업자 역할을 확인합니다. 담당자가 제조사 절차로 비상정지 상태와 반응을 확인합니다. | 작업 영역, 사람의 위치, 고정 상태, 격리 네트워크와 작업자 역할을 확인합니다. 담당자가 제조사 절차로 비상정지 상태와 반응을 확인합니다. |
| 읽기 전용 상태 | `hw-enlight-01`에서 관절 상태, 제어 모드와 오류·비상정지 상태를 읽는 범위를 확인합니다. | `hw-fr3-01`에서 읽기 전용 상태와 섀도 검증의 범위를 확인합니다. |
| 자유공간 궤적 준비 | `hw-enlight-03`의 궤적과 실행 카드 준비를 읽습니다. | `core-fr3-09`의 관절·TCP 궤적을 시뮬레이션에서 검토하고 `hw-fr3-01`의 게이트를 따릅니다. |

먼저 로봇을 연결하기 전에 수집된 상태의 타임스탬프가 늦어지는 경우를 예측합니다. 오프라인 런타임 `hw-common-01`은 고정 관측에 대한 후보 정책의 출력과 저장된 참조값을 대조하고, 결과를 명령 차단 수신기에 기록합니다. `command-sink.json`에서 모터 명령을 발행하지 않는 경로를 확인합니다.

현장에서는 모델 일치와 읽기 전용 로그, 제한, 감시 타이머, 오래된 명령에 대한 차단, 제어 권한과 정지 경로를 먼저 확인합니다. 자유공간 궤적은 시뮬레이션에서 관절각과 TCP의 시간 기록, 충돌 여유 및 속도·가속도 제한을 검토합니다. 실제 움직임이 필요한 실습은 해당 로봇, 모드, 부분 시스템, 동작과 제한을 명시한 실행 카드와 그 실행에 대한 별도 승인으로 진행합니다. 접촉 과제도 별도 승인을 거칩니다. [저장소 안전 지침](https://github.com/terryum/tutorial-robotics/blob/main/docs/07_SAFETY.md)

## Enlight와 Wuji Hand 2 · 시연에서 후보 정책까지

**기존 기록 · 팔 합성 시연과 BC**　**현장 확인 대기 · 통합 로봇과 과제**

1. Enlight 팔의 목표와 Wuji Hand 2의 손가락 목표를 별도 이름·관측·제한으로 정의합니다. 좌우 및 탄젠트 방향, 손 마운트 프레임과 손가락 관절 순서를 대조합니다.
2. 시뮬레이션 수집에서 손목이 움직이는 구간과 손가락을 굽히는 구간을 표시한 뒤 각 시연을 재생합니다. `sim-enlight-06`은 팔의 수집·재생 경로를 제공합니다. 이 경로에서 팔 단독 BC를 실행해 에피소드 분할, 관측·행동 차원, 정책 재로딩과 독립 도달 결과를 읽습니다.
3. 팔과 손을 결합한 정책은 같은 에피소드에 두 동작이 함께 들어 있는지, 목표와 상태의 프레임이 맞는지 먼저 오프라인에서 검사합니다. 시뮬레이션 PPO 후보를 평가할 경우에는 집기·이동·놓기 성공을 독립 과제로 정의하고, 관절 한계와 물체 접촉을 함께 확인합니다. 후보 파일의 모델·입력·정책 해시, 테스트 벡터와 차단 상태를 기록합니다. `hw-enlight-wuji-01`에서는 통합 읽기 전용 절차를 준비합니다.

**한 변수.** 카메라와 팔 정책은 고정하고 손가락 관측의 시각만 늦다고 가정합니다. 시연 재생 시 어느 프레임에서 물체가 손에 들어가는 것으로 보일지 예측하고, 카메라와 실제 손가락의 정렬이 틀어졌을 때 성공 판정에 어떤 영향을 주는지 설명해 보세요.
